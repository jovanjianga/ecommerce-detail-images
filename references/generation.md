# 内置图像工具执行与一致性

此 Skill 负责组织工作流，实际图片必须由当前环境可用的图像生成工具产生。执行时以工具当前文档和上级指令为准；不假定固定模型名、尺寸参数或返回文件字段。

## 工具选择

- 默认使用内置 `image_gen`。批量意味着每张独立调用，不意味着切换到 API。内置模式无需用户提供 API 密钥。
- 不用 HTML、SVG、网页截图或代码画占位海报代替用户要求的商品图片。
- 内置工具不可用或持续失败时，报告具体阻碍并保存计划、提示词和已成功图片。只有用户明确选择 CLI/API 后才采用该路径；如果安装的 `imagegen` Skill 可用，读取它的对应后备流程。
- 创建本 Skill 的验证不需要自动生成十张演示图。真实出图属于用户使用本 Skill 时的任务。

## 传入参考图片

- 使用本地图片前先通过图像查看工具检查。
- 当前工具支持 `referenced_image_paths` 时，只在全部目标图片有本地路径时使用它。
- 至少一张目标图片仅在会话中时，使用 `num_last_images_to_include`，取能包含全部目标的最小数量，最多 5 张。不能同时使用这两个参数。
- 生成多页会让原始附件移出最近图片范围。优先保存工具返回的实际文件或将已存在的本地素材重新查看，再使用对应引用机制；不得悄悄只引用最近生成图而丢失真实商品参考。两种机制均无法覆盖必要素材时，请用户重新附上缺失图片，再继续依赖它的页面。
- 完全无图的第一张生成不要传任一参考参数。只提供文字时，以生成的基准图继续，明确其为概念外观。
- 风格图与 Logo 也算参考输入；参考过多时只选择本页必要的素材，并明确各自角色。

## 生成顺序

1. 首屏或外观基准：核对商品外观与设计方向，必要时做一次针对性修正。
2. 其余页面：每次传入原始商品依据，加合适的基准图/Logo，以及本页完整提示词。
3. 一张页对应一个独立成品，不让工具一次生成十格拼图来冒充十个文件。
4. 全局风格基准不合格时，不把它扩散到剩余页面；明确阻碍，保留已完成工作。

长时间调用遵循当前工具的等待说明。收到运行中状态就续等该任务，不重复提交相同页面。工具完成后展示其原生图片结果（在 `functions.exec` 环境按文档使用 `generatedImage(result)`），不打印 base64 数据。

照片通常使用非透明背景；只有用户要求透明图层/Logo 时设置透明背景，编辑已有透明素材时保留透明度。9:16 等比例写进提示词，检查实际结果；工具不提供精确尺寸控制时，不虚称已经得到指定像素。不得静默裁切商品或文字以强行适配尺寸。

## 保存、恢复与修改

- 记录图像工具实际返回的文件位置或原生结果。若提供本地路径，复制到项目的 `images/` 并按页码命名；具体文件格式保留真实扩展名。
- 如果工具只返回内联媒体，则如实展示媒体并说明未取得可下载的本地文件，不把这种结果写成存在的磁盘文件，不使用未经支持的提取方式。
- 若当前页调用结果未知，先检查已返回的任务状态/产物，再决定是否重试。恢复任务时按 `delivery.md` 检查实际文件，跳过已完成页面，仅补缺失或不合格页面。
- 每页状态区分「待生成」「已生成待检查」「检查通过」「需修正」「失败」。工具成功不等于视觉检查通过。
- 修改图片使用内置图像编辑流程，传入实际待编辑图和必要的商品参考。明确「仅改变 X，保留 Y」，在新版本上重新检查。
- 不自行用 Python 处理图像、裁切、贴字或拼接。用户明确要求其他处理方式时再按其要求执行。

页面命名可以采用 `01-hero.png`、`02-benefits.png` 等；修改后使用 `02-benefits-v2.png`。项目文件中的路径必须指向实际存在的产物。
